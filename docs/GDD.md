# 冷宫开席游戏设计文档

- **版本：**0.4
- **用途：**立项讨论与可玩原型开发
- **改编参考：**《冷宫开席：陛下又来蹭饭了》

## 一、项目定位与内容依据

本作是一款以冷宫生活为背景的轻经营游戏。玩家从寻找野菜、做出第一顿饭开始，通过种植、烹饪、改善住处和建立人物关系，把资源匮乏的冷宫逐渐经营成能够自给、有人来往的小院。

**核心机制是通过一顿饭改变来人的态度，化解眼前难题，再把对方的帮助转化为下一轮生产能力。** 日常采集、种植、修屋和人物往来，为每次关键做饭提供食材、器具与线索；中秋嘉宴则将这套能力放大为公开献菜挑战。

**核心玩家幻想：**我凭自己的生活本领和经营判断，在不被看好的处境中站稳脚跟，用一顿拿手饭让轻视、刁难我的人改变态度，把困境变成新的机会。

### 内容依据

**用户提供的剧情信息：**女主被皇后发配冷宫；初期寻找野菜，随后获取种子、种菜做饭并改善生活；看管太监起初轻视她，吃过第一顿饭后态度转变，愿意帮忙带种子和传话；皇帝以御前侍卫等身份来到冷宫，不希望在这里被称为皇帝；皇后因这些往来发难，可能没收物资、破坏菜地或诬陷女主偷取皇帝的东西；宫宴要求各宫献菜，女主需要在食材分配受到阻挠时设法完成菜品。

**用户补充的核心剧情机制：**每次遇到查办或刁难，女主会做一顿饭给负责处理此事的人吃，对方吃过后放过她。该规律作为本版核心改编依据；各事件中的具体人物、菜式与结局仍待剧本核对。

**用户新增的开局细节：**冷宫里发现的物品可有多种用途；秸秆可烧火，清理的草可制肥；太监参与挖野菜，女主第一次给太监吃的是野菜汤。“秸秆”“杂草”为本版对口述词语的暂用整理，具体植物待确认。

**原创设计：**资源规则、劳作分配、关系阶段、设施功能、事件判定、菜谱、关卡流程与界面布局。

**待验证假设：**竖屏操作、经营日长度、前期反馈速度、作物周期、事件频率，以及玩家是否喜欢持续进行资源与建设决策。

当前未依据完整剧本逐集核对，不确定女主何时识破皇帝身份，也不确定具体人物姓名、物品和宴席菜式。原型暂用角色代称。

## 二、产品目标与设计支柱

目标平台暂定为移动端竖屏，支持单手点击操作。目标玩家是假设中同时对种田、美食、建设与人物反转感兴趣的轻度经营用户，需通过试玩验证。

1. **低门槛操作。**采集、种植、烹饪与修缮都能直接从场景发起，首次操作不依赖长教程。
2. **资源有用途竞争。**同一批菜可能用于自食、留种、分享或交换，玩家需要考虑眼前需求与后续供给。
3. **人物关系带来实际渠道。**做饭与交往改变人物态度，人物再帮助玩家取得无法自产的物资或传递消息。
4. **成长可见。**床铺、灶台、菜地和储物空间逐步改善，经营成果留在场景里。
5. **用美食完成反转。**查办者带着任务来到冷宫，玩家为其准备合适饭菜，让他从冷淡或强硬转为放行。难点来自选菜与筹备，人物转变提供集中回报。

## 三、核心循环与阶段目标

**日常循环：**查看库存与来访线索 → 采集、种植和修缮 → 储备食物与完善做法 → 为人物做饭 → 获得帮助与渠道 → 进入下一日。

**核心解困循环：**麻烦到来 → 确认谁负责处理 → 通过交谈或太监了解口味 → 选择菜谱 → 调用食材与渠道 → 烹饪招待 → 对方态度反转并放行 → 获得下一阶段机会。

**章节循环：**日常积累 → 遇到更高要求的招待或宫宴 → 在阻挠中筹备 → 完成关键一餐 → 关系与处境改善 → 开放新配方、设施或渠道。

通关的主要动作是做饭。聊天和传话用于了解来人、寻找食材及争取筹备机会，查证与作证不再构成独立核心系统。

| 阶段 | 主要目标 | 阶段成果 |
|---|---|---|
| 求生 | 找食物，做热饭，整理住处 | 能维持基本生活 |
| 立足 | 获取种子，完成首轮种植 | 有可预期的食物供给 |
| 改善 | 修屋、扩充烹饪与储备能力 | 对单一渠道的依赖降低 |
| 应对 | 为处理麻烦的人做出合适饭菜 | 当次放行，可能建立新联系 |
| 证明 | 完成宫宴献菜 | 能力被公开认可，开放新机会 |

阶段推进以完成关键行为为准，不固定绑定现实天数。

## 四、资源与经济规则

首版不使用通用金币购买全部物品。物资主要来自采集、自产、份例、人物帮忙与明确交换。

| 资源 | 主要来源 | 主要用途 |
|---|---|---|
| 食材 | 采集、种植、份例、交换 | 自食、烹饪、任务交付 |
| 种子 | 人物带来、留种或特定交换 | 建立后续生产 |
| 燃料与修缮材料 | 清理旧物、份例、人物渠道 | 做饭、修屋与设施建设 |
| 成品食物 | 烹饪 | 自食、分享、交换、献菜 |
| 每日劳作 | 经营日开始时获得 | 限制当日可完成的行动 |

燃料在开局即以秸秆等具体物品呈现，让玩家理解拾取物如何支持做饭；不再把燃料完全隐去。肥料在第一次准备菜地时介绍，不额外增加复杂养分指标。

人物信任采用事件状态与可办事项呈现，不作为任意购买物资的通用货币。

### 基础规则

- 每日需安排一份自用食物，不采用实时饥饿倒计时。资源不足时允许通过基础采集继续生活，但会推迟其他目标。
- 当日结余物资进入次日。新鲜食物、干粮与种子的保存条件分别明确显示；首版不加入复杂腐败系统。
- 每日劳作在进入新经营日时恢复，不随现实时间恢复，也不允许通过反复切换日程复制资源。推进一天会同步推进作物、人物约定和事件期限。
- 首轮教学保证完成核心链条所需的资源。正式经营后，劳作与物资不能支持每天完成全部目标。

### 一物多用与物资转换

环境中的旧物和植物具有可发现的用途，清理场景同时获得生活物资。下表中秸秆烧火、草制肥来自用户补充；其余用途及具体转换规则为原创方案。

| 物品 | 获取方式 | 用途与转换 | 取舍 |
|---|---|---|---|
| 秸秆 | 拾取场景中已有的干秸秆，后续来源另行配置 | 作为烹饪燃料；也可铺覆菜地保湿 | 当次烧饭或留给后续照料 |
| 杂草 | 清理院落和待开垦区域 | 清出可用空间；收集后投入简易堆肥处制成肥料 | 先用劳作制肥，或优先烹饪与修缮 |
| 肥料 | 杂草经过加工后获得 | 用于菜地，改善指定种植周期的产出 | 当前使用或留给更重要的一茬 |
| 野菜 | 太监参与挖取，后续由玩家或明确帮忙获得 | 制作野菜汤；合适植株可移栽 | 即时食用或建立持续供给 |
| 旧木料 | 清理旧棚等指定场景 | 可用木料修缮；不可修用的干木作为备用燃料 | 保留建设材料或应急生火 |

一物多用不表示物品可重复消耗。同一份秸秆用于烧火后便扣除，不能同时铺地；杂草在清理后成为库存材料，再经加工变成肥料，不会凭空复制。

“化肥”在玩法中暂统一称肥料或堆肥，符合草料加工的用途。杂草不会即时自动转化；加工消耗与经营日周期需原型验证。首轮施肥是改善生产的选项，不是首次播种的硬门槛。

点选物品可查看已知用途及对应设施。先展示当前能用的一项，后续解锁另一用途，避免首次拾取就出现过多按钮。

## 五、采集与种植系统

采集范围限定在冷宫院内及剧情允许接触的周边区域。地点是否开放，由清理进度、工具或许可决定。

首次野菜采集由太监参与挖取，女主辨认并安排用途；其是否由玩家直接指派或通过剧情共同采集，暂采用一次明确的帮忙互动实现。太监此时可以因女主指点或顺手帮忙而参与，态度仍敷衍，不提前触发吃汤后的认可。采集采用固定结果，玩家通过女主的知识提示辨认可食用植物。采集动作提供即时反馈，不依靠误食猜谜制造困难。

采集点显示剩余数量与恢复条件。基础野菜提供保底生活来源，但不足以支持全部交换和章节目标。

**种植流程：**清理土地 → 获得种子 → 播种 → 必要照料 → 收获 → 决定食用、加工或保留繁育条件。

首版只实现一种作物，验证种植能否形成跨日计划。扩展后再区分快收叶菜、耐储存作物与调味植物。

作物按游戏内经营日生长。正常离线不会造成枯死。照料采用批量操作，避免逐株重复点击。

留种按作物设置条件，例如保留植株继续成熟，并占用土地。不能默认所有收获都能立即转换为种子。

种植取舍主要来自土地、成熟时间、劳作和收获用途，而非大量重复操作。

## 六、烹饪与食物分配

烹饪是解决主要冲突的核心行为，同时承担维持生活与建立合作的作用。

### 招待判定与玩家决策

每次关键招待公开必要条件：人数与份量、已经知道的口味或忌口、必需制作条件。隐藏偏好只影响额外认可，不决定基础通关。

玩家通过短对话、此前来访记录或太监传话获得偏好线索。原型先使用家常、清淡、香脆等少量标签，不要求猜选项。符合公开条件并完成制作即可获得当次放行，不以隐藏概率决定是否吃了还要处罚。

至少提供两种可行筹备方式，例如使用现有菜谱，或请太监补来材料制作另一道菜。选择改变消耗、剩余储备和后续安排。不是每次都寻找唯一一道指定答案。

反复招待通过食材限制、口味差异、份量、器具和时间安排形成变化。更贵的菜不自动更有效；合适的家常菜也能完成关卡。

**结果分层：**达到条件即解决当前麻烦；额外匹配偏好可获得线索或一次帮忙；长期成为可靠渠道需后续明确互动，不把所有查办者吃完一顿饭都变成永久盟友。

未达条件时指出具体缺口，并在可用条件下允许补做或换菜。关键教学事件保证可获得所需基础材料，不先没收灶台和全部食材再要求做饭。

玩家选择菜谱后，界面显示食材、设施、劳作消耗、产出份数和制作后库存。确认后完成简短制作表现，重复烹饪可简化操作。

首道固定菜谱为野菜汤，用于自食及第一次招待太监。配方包含野菜、清水、秸秆等燃料与可用锅灶；清水来源在场景中明确交代，首版通过固定取水点提供，不展开水资源经营。是否有初始调料待剧本核对，未取得的食材不加入强制配方。第二款菜用于测试不同资源消耗与后续招待，具体菜名待定。

饭菜完成后，玩家决定分配方式：

- 自食保障当日生活。
- 储备减少次日准备压力。
- 分享推动具体人物互动。
- 交换补齐无法自产的物资。
- 招待查办者化解当前难题。
- 宫宴交付推进章节。

烹饪不设置自由售价，不以随机普通顾客构成营业循环。

公宴菜品在基础烹饪上增加配方、份量、加工与装盘要求。前期不将全部菜都拆成复杂质量数值。

## 七、屋舍与院落改造

改造解决具体生活问题，并改变经营能力。

| 改造 | 主要作用 | 视觉变化 |
|---|---|---|
| 清理屋内与床铺 | 恢复可用生活空间 | 杂乱角落变得整洁 |
| 修补屋顶 | 保护对应区域免受雨水影响 | 漏水停止，储物位置恢复可用 |
| 修复灶台 | 开放新的制作方式 | 灶台完整，器具增加，可满足新的招待做法 |
| 整理储物架 | 整理物资并提供明示的遮雨位置，首版不设容量上限 | 种子与食物分类放置 |
| 开垦菜地 | 增加生产空间 | 荒地变为菜畦 |
| 修整桌凳 | 支持共同用餐及来访事件 | 院中出现可使用的饭桌，让关键招待和态度变化可见 |

首局完成一项小改善，尽早兑现建设成果。完整修屋留作后续目标。

每项改造在确认前展示材料、劳作、施工条件和完成后的用途。施工若占用灶台等设施，需提前提示。

改造选择来自顺序：先修屋顶保护储备，还是先开地争取早收获；先修灶台做更多菜，还是先改善储存条件。

永久改造原则上保留。反派事件可以暂时影响使用或造成明确局部损坏，不能频繁将已完成建设全部归零。

## 八、人物关系与渠道

### 看管太监

他是前期连接冷宫与外界的关键人物。初次出现时轻视女主的折腾；喝过玩家做出的第一碗野菜汤后迅速改变态度，愿意帮助女主。

这次转变通过动作、对白和可用请求共同呈现。饭前敷衍，饭后主动询问缺什么，是首局的重要情绪回报。

太监首次参与挖野菜时仍不以为然，女主利用这些野菜煮汤；他尝到汤后，从顺手帮忙转为主动支持。

第一碗野菜汤后即可开启首批种子任务，不要求反复赠礼刷基础好感。后续成长来自共同办事：带回种子、完成交换、传递消息、提醒风险。

他愿意帮助，但仍受值守、来源和权限限制。请求显示所需物品、预计完成节点与是否确定可办。重复送同一道菜不能无限换取物资。

### 皇帝

皇帝以御前侍卫等身份来到冷宫，并要求不在此称呼其皇帝身份。

初期作为饭友参与：品尝、交流、提出具体需求，逐步建立来往。玩家是否知情与女主是否知情分别管理，准确节点待剧本核对。

皇帝的饭友关系同样通过玩家做出的饭菜发展。遇到查办事件时，优先由玩家完成招待解决当次麻烦，避免皇帝自动出面替代核心玩法。

### 皇后

皇后构成持续的外部压力。她的行动围绕克扣物资、局部破坏、限制渠道与诬陷展开。

冲突的作用是改变计划、检验准备，并为阶段反转积累情绪。不是每天固定扣除玩家成果。

### 其他渠道

后厨等人物在后续开放。每条渠道说明接触方式、提供能力与交换需求。大臣等人物不能默认自由进入冷宫，需有剧情认可的传递路径。

## 九、事件系统

事件必须改变至少一项经营决定：资源用途、行动顺序、菜谱、建设或请求对象。

每个冲突事件需配置触发条件、预告、影响范围、负责处理的人、已知口味、招待条件、可用配方、食材渠道、放行结果与额外回报。一般生活事件仍可直接用劳作处理，无需所有小事都插入招待。随机事件受当前进度和资源约束，不抽取玩家尚无应对能力的组合。

| 事件类型 | 示例 | 主要选择 |
|---|---|---|
| 天气 | 明日降雨 | 修屋、转移物资或优先种植 |
| 供给 | 份例减少或缺少关键材料 | 采集补缺、调整配方、动用储备 |
| 人物 | 太监本次只能完成一项帮忙 | 带种子或传递消息 |
| 阻挠 | 皇后手下来查物资 | 了解查办者口味，安排招待并保留后续储备 |
| 机会 | 得知某处可交换面粉 | 使用现有食物或保留口粮 |
| 诬陷 | 被指控偷取皇帝物品 | 为查办者选菜、补料、做饭，促成当次放行 |

关键剧情事件固定或条件触发；资源与来访变化可采用受约束随机。首次教学不随机阻断种子或基础食物来源。

同一经营日原则上只有一个主要冲突。首次破坏可以用于建立威胁，后续类似风险应提供线索和补救空间。

## 十、做饭解困小关卡

皇后的指控、查物资或封菜地构成事件起因。玩家的主要任务是为负责处理此事的人准备一顿合适的饭，促使其放行。

**流程：**查办者到来 → 短对话交代麻烦与招待机会 → 查看口味与要求 → 选择菜谱和物资方案 → 做饭上桌 → 试吃与态度变化 → 撤回当次处理或停止继续追究 → 恢复经营。

“放过女主”的具体表现按事件配置，例如取消本次没收、归还本次暂扣物资、允许继续使用菜地或结束本次追究。这是当次处理结果，不等同于永久平反或皇后停止针对。

查办事件须在设定中留出可执行的招待机会，例如来人尚在等待、允许先备饭，或太监能帮忙留人。不能一边要求立刻执行，一边让玩家无解释地完成数日种植。

对已经毁坏的作物，吃饭后的放行只阻止继续破坏，不会凭空恢复收成。之后通过补种与渠道恢复生产。

**情绪呈现：**来人起初冷脸催办；闻到香味后停顿；试吃后主动夹第二口；语气缓和，宣布当次放行。玩家能清楚看到转变由自己完成的菜触发。

不设置寻找证据、证人拼图或身份揭露作为必要通关条件。往来记录仅辅助记住口味、请求与物资来源。

## 十一、宫宴大关卡

中秋嘉宴要求各宫献菜，女主需要在物资分配受到阻挠的情况下完成合格菜品。

关卡按游戏内筹备日推进，期限不会因离线流逝。

**流程：**收到要求 → 检查物资 → 确定菜谱 → 安排自产与渠道 → 应对阻挠 → 制作装盘 → 交付评价。

通过底线是明确的份量、必要加工条件和按时交付。风味与外观完成度决定额外评价。所有要求在筹备阶段可见。

至少提供两条可行路线，例如维持原菜谱并寻找缺失食材，或改用符合要求的替代菜谱。路线差异来自玩家此前积累。

宫宴延续“靠做出的饭菜改变评价”的核心，但要求服务多人、满足宴席规格，不能用随意招待一位来人替代正式献菜。结算先展示成品与试吃评价，再说明自产食材、设施与人物帮助如何促成结果。奖励优先开放新的经营能力，例如工具、配方或正式申请渠道。

结果不足时给出可解释的较低评价或补救目标，不清空存档。

## 十二、首局吸引力与体验节奏

首局目标是在约六分钟内完成一次小翻身，具体时长待测。

| 阶段 | 玩家行为 | 主要回报 |
|---|---|---|
| 快速入戏 | 发现野菜、秸秆和杂草，短对话辨认用途 | 明确野菜汤所需物资 |
| 第一次成果 | 太监参与挖野菜，玩家拾秸秆、取水、生火煮汤 | 零散环境物资变成一锅热汤 |
| 人物反转 | 太监喝第一碗野菜汤 | 从轻视变为愿意帮忙，首次示范核心机制 |
| 主动请求 | 提出种子需求 | 厨艺转化为渠道 |
| 可见成长 | 清草整理菜地，保留草料供制肥；改善一处住处 | 清理既改变场景，也带来可用物资 |
| 后续期待 | 接到种子并播种 | 明日有新的生产目标 |

首次太监交付种子可安排在同日稍后，玩家利用等待节点完成清理。不得用现实等待阻断首轮体验。

首局操作链明确为：辨认用途 → 太监参与挖野菜 → 拾取秸秆并取水 → 生火煮野菜汤 → 请太监喝汤 → 态度反转 → 请求种子 → 清理菜地并收集草料 → 播种。清草制肥作为紧随其后的扩展，不阻断首轮招待。

第一碗野菜汤对太监的转变就是最早的核心机制教学；之后的首次查办沿用同一动作链，增加一种已知口味和一次资源选择，无需重学证据规则。

首局结算是自然结束点，玩家已得到完整成果。宫宴和神秘饭友可以预告，但不抢占第一次经营的操作时间。

## 十四、完整解困经营日示例

以下为原创关卡与数值，用于验证核心机制，不代表原剧具体菜式或台词。

**事件：**皇后派人前来，以女主私拿宫中物品为由准备没收一批物资。太监先替女主留住来人，争取本经营日内准备一顿饭的机会。来人尚未执行没收，玩家能使用库存与灶台。

短对话告知：来人喜欢热乎的家常面食，不吃辣。招待需一份，自己还需一份饭。两种已解锁配方均可满足：野菜饼或清汤面。此处不设置隐藏成功率。

日初库存为野菜四份、面粉一份、种子一包、修缮材料一组，今日四次劳作。原本计划修屋并播种，事件迫使玩家调整。

| 行动 | 消耗 | 产出或效果 |
|---|---|---|
| 制作野菜饼 | 野菜两份、面粉一份、一次劳作 | 两份菜饼，满足本次招待 |
| 请求太监补面粉 | 一次劳作及本次帮忙机会 | 当日约定节点带回一份面粉；本事件已交代可用来源 |
| 制作清汤面 | 野菜一份、面粉两份、一次劳作 | 两份清汤面，满足本次招待 |
| 修屋顶 | 修缮材料一组、两次劳作 | 完成修补 |
| 播种 | 种子一包、一次劳作 | 启动作物生长 |

上桌与试吃纳入对应烹饪行动，不再额外扣劳作。

**方案一：用现有食材解困。**做菜饼，招待一份、自用一份，再修屋与播种，合计四次劳作。结算为野菜两份，面粉、种子和修缮材料均已使用；屋顶修好，作物开始生长；太监本次帮忙机会保留。

**方案二：保留更多野菜。**请求面粉、做清汤面，再修屋，合计四次劳作。招待一份、自用一份。结算为野菜三份、种子一包；面粉与修缮材料用完；屋顶修好，播种推迟；太监本次帮忙机会已使用。此方案可以保留野菜应对下一轮需求，但放弃了当日播种。

两条路线都促成来人放行，不强行把更费事的做法判为更高分。玩家选择取决于后续计划。

结算先表现来人从冷淡到吃得投入，再明确取消本次没收。之后展示库存、建设与种植的差异。主要奖励是保住原有物资和恢复经营；可另获得一条人物线索，不必每次额外发放大量资源。

## 十五、界面与操作布局

竖屏主场景采用纵向冷宫小院。

- **上方为屋舍：**展示床铺、储物和修缮。
- **中部为灶台、小桌与人物活动区：**承载选菜、烹饪、关键试吃与人物态度反转。
- **下方为野菜与菜地：**承载高频操作。
- **院门位于侧边：**承载来访和交付。

玩家点击场景对象直接操作，信息就近展开。采集显示数量，菜地显示进度，灶台显示配方，修缮处显示投入与收益。

冲突到来时显示“谁来查办—已知口味—本次需准备什么—完成后解决什么”，可点入比较配方消耗，不把人物态度压缩成一个不明概率。

物品详情显示多种用途，消耗前预览剩余数量。例如秸秆显示“烧火”“铺地”，未解锁用途只作简短提示。烹饪缺燃料时可定位场景中明确可拾取的秸秆。

顶部常驻今日目标、剩余劳作与必要提醒。库存和往来记录收在入口中，不让全部物资铺满屏幕。

日末展示库存、作物、建设和人物事项，优先突出场景变化。关键选择前可预览消耗，提交与交付需明确确认，避免误触。

## 十六、成长与复玩

长期成长包括生产空间、烹饪方式、储备能力、人物渠道和章节机会。升级应带来新的选择，不能仅让产量数字持续膨胀。

变化来自来人口味、可用菜谱、食材缺口、事件组合、建设顺序和不同筹备路线。同一做饭解困结构下，要让玩家实际更换方案，避免所有关卡都点击同一道菜。第一阶段不强制加入局局重置的肉鸽结构。

完成关卡后可以继续经营，后续再测试宫宴重试或不同方案挑战。是否需要独立复玩模式，依据原型结果决定。

持续游玩依靠可见成长、有效策略和人物期待，不依赖惩罚离线、误导倒计时或突然清空成果。

## 十七、MVP开发范围

### 第一阶段：验证基础循环

一个院落与屋内场景；一种野菜、一种作物、两款基础饭菜（首道为野菜汤）；秸秆燃料、杂草制肥及一个多用途选择；固定取水点；简化库存与每日劳作；三项改造；太监首次转变及种子请求；分类背包、物品用途面板、缺料定位、可撤销物资预留和人物约定记录；日末结算；六个事件模板。首版背包与屋内储物均不设容量上限。

### 第二阶段：验证短剧式章节

加入皇帝隐姓来访、两位偏好不同的查办者、两段做饭解困关卡和一场宫宴。基础两款菜不足以覆盖验证时，再增加一款具有不同资源消耗的菜；扩展与之相关的物资渠道，不开发证据与作证系统。

首版不做多地图、多店、自由定价、普通客流、复杂养殖、多角色恋爱或完整宫斗系统。

基础循环若不能让玩家主动继续，先调整操作与取舍，不急于扩展剧情量。

## 十八、原型实现与验收

关键状态包括经营日与阶段、库存、菜地状态、设施状态、人物约定、人物口味、已知身份、当前查办者、招待要求、放行状态、事件标记和章节目标。

采集、烹饪、交换与建设均记录明确的输入输出，避免重复交付。人物请求有待办、进行中、完成或失效状态。

存档保留已确认操作与章节进度，恢复后不重复领取奖励。事件依赖按当前状态判断，避免太监尚未建立帮助关系就出现高级传话任务。

### 基础验收要求

- 玩家能够独立完成采集、烹饪、分配、获种和播种。
- 库存流转正确，多用途物品按所选用途只消耗一次。
- 首次野菜汤具有可获得的野菜、清水、燃料和可用锅灶，太监在喝汤后而非采集时触发态度转变。
- 清草获得材料、制肥加工和施肥分别正确结算，未施肥也可完成首轮种植。
- 至少两种建设顺序可以继续经营。
- 请求按约交付。
- 缺料提示只引用实际存在的已知途径，预计交付不计入持有库存。
- 原料预留可取消或改分配；任务完成后无残留锁定；更换方案不会重复预留。
- 自动读取背包与屋内可用物资，多用途建设材料不会未经确认被当作燃料。
- 两种可行筹备路线都能通过对应招待，库存正确扣除，放行结果只结算一次。
- 达标后不会因隐藏随机判定遭处罚；不达标时说明原因并提供合理补做路径。
- 退出恢复后进度一致。
- 首轮失败不会永久卡死。

## 十九、测试计划与立项判断

首轮采用约八至十二人的观察式试玩，结果用于发现问题，不作为市场规模或留存结论。

记录首次有效操作时间、核心循环完成情况、需要解释的位置、主动选择及第二日开始行为。

重点访谈玩家为什么为来人选这道菜、为凑齐材料改变了什么计划、是否注意到吃饭前后的态度变化，以及是否认为放行来自自己的准备。

分别观察玩家对经营和剧情的兴趣。主动等待人物剧情，不等同于愿意重复经营。

| 观察到的问题 | 优先调整方向 |
|---|---|
| 玩家认为每次都是随便做一道菜就过 | 调整公开口味、配方消耗与筹备条件，验证不同策略 |
| 玩家只等着看吃饭动画 | 缩短重复演出，增强选菜与资源安排的作用 |
| 玩家认为全部选择都一样 | 调整资源与后果 |
| 主要时间用于重复点击 | 简化操作 |
| 破坏事件让玩家觉得此前努力无效 | 缩小影响并强化预判 |
| 需要持续提示才能完成 | 降低首局复杂度 |

进入下一阶段的依据是：玩家能够理解循环，能说清自己的取舍，能感到成果来自行动，并主动想继续一次经营。

## 二十、做饭解困的操作与配套系统

本章为原创实现方案。目标是让玩家始终知道要招待谁、做什么、缺什么、如何取得，以及做完后解决什么。下列系统均服务于这条链，首版不额外扩展装备、负重、耐久或复杂腐败。

### 1 背包与屋内储物

背包承接拾取和临时携带，屋内储物承接存放。冷宫场景内制作、建设和交付读取两者的合计可用库存，不要求玩家搬运后才能做饭。两处库存仍保留实际存放位置，供剧情中的明确局部影响使用；界面预留标记本身不构成防没收保护。

| 项目 | 首版规则 |
|---|---|
| 分类 | 食材、种子、燃料材料、饭菜、特殊物品 |
| 拾取 | 自动进入背包，显示物品及获得数量 |
| 堆叠 | 同类同状态物品合并，原料和成品分开 |
| 容量 | 首版不设背包或储物容量上限，不使用重量 |
| 存放 | 可批量存放；不改变数量、不消耗劳作 |
| 特殊物品 | 独立分类，不能误吃、误烧或误丢 |
| 排序 | 默认按分类稳定排序，新获得物品短暂标记 |
| 数量展示 | 显示持有、已预留、可用；预留部分仍属于持有量 |

储物架首版提供整齐摆放和经明示的遮雨储存功能，不以容量扩张作为必要升级。容量玩法后续如需引入，应单独验证，不与本版无限容量同时生效。

### 2 物品用途面板

点击秸秆显示持有数量、已知用途、所需设施和消耗。例如“烧火：制作野菜汤需一份”“铺地：解锁对应菜地功能后可用”。点击用途跳到相关对象，跳转不直接消耗。

普通制作只使用配方认可的材料。存在多种燃料时，优先推荐单一用途燃料；可用于修屋的木料必须由玩家明确选用，不能静默替代秸秆。

尚未解锁的用途仅显示简短说明。使用前展示会消耗多少、剩下多少，以及是否动用预留物资。杂草制肥在独立加工步骤结算，不能点开用途就自动转换。

### 3 招待目标与选菜

查办者到来后显示本次目标、已知要求、筹备截止节点及达成后的放行结果。要求由关卡配置，不要求每个人都具备复杂口味。

菜谱列表分为“可制作”“缺材料”“缺设施”，同时标出是否符合本次招待要求。玩家即使能制作某道菜，也能在消耗前看见它是否符合已知忌口与份量要求。

选择菜谱后，统一显示食材、清水来源、燃料、设施、劳作、产出份数与消耗后库存。现有成品符合条件时可直接用于招待，首版不强制每次重做。

### 4 缺料与获取提示

| 缺失条件 | 提示方式 | 行为边界 |
|---|---|---|
| 野菜 | 定位仍有产出的已知采集点 | 耗尽时明确显示，不能凭提示无限刷新 |
| 燃料 | 定位可拾秸秆，或展示明确可用的替代燃料 | 使用多用途木料仍需确认 |
| 面粉等外来食材 | 列出已建立的人物请求或交换 | 显示代价与交付节点，不承诺立即到账 |
| 清水 | 定位固定取水点 | 首版取水无独立库存消耗，首次演示后并入制作表现 |
| 器具 | 定位对应修缮或借用渠道 | 显示完成所需劳作与时间 |
| 劳作 | 提示剩余量及当前方案总消耗 | 不把补给尚未送达算作今日可用 |

获取途径仅展示已知且实际存在的内容。没有可用途径时提示尝试其他菜谱；若关卡全部路线均不可达，属于事件生成问题，不能让玩家盲目寻找不存在的材料。

### 5 物资预留

玩家可为自食、招待、交换或后续生产标记数量。一个单位同一时间只能归属一个预留事项，不能同时被两件事占用。

选定招待方案时，先预览所需物资，确认后预留当前已有数量；未取得的材料仅列为缺口。取消或更换方案立即释放旧预留，再按新方案计算。

其他行为将消耗预留物资时，需提醒并允许玩家明确改计划。系统不得偷偷消耗，也不能把预留设计成无法撤销的锁。任务完成或取消后释放剩余预留。

成品自食与招待分别分配。若制作两份，一份自食、一份待客，两份在制作后分别标记，避免自动吃掉客人的那一份。

### 6 人物小册与约定

人物小册记录已知口味及其来源、最近一次态度变化、当前可请求事项，以及已答应事情的交付节点。未知口味不提前揭示。

太监的种子请求应显示“已答应—何时带来—所需物品”，完成时明确入库。向太监打听查办者喜好，记录得到的信息，而非直接增加抽象成功率。

玩家查看记录和浏览配方不消耗劳作。需要实际办事的打听、补料与传话，按关卡明示规则扣劳作或占用帮忙机会，不因打开界面扣除。

### 7 从接到麻烦到放行的完整流程

| 步骤 | 玩家看到什么 | 玩家操作 | 状态与库存变化 |
|---|---|---|---|
| 接到麻烦 | 来人、影响与本次招待机会 | 查看目标，与来人交谈 | 进入筹备，尚未消耗材料 |
| 确定方案 | 已知要求和候选菜谱 | 比较并选择 | 记录方案，确认已有物资预留 |
| 补齐缺口 | 缺料及已知渠道 | 采集、请求、交换或修缮 | 各行动按规则结算，未来交付仍为待办 |
| 确认制作 | 全部实际可用条件和制作后余量 | 点击制作 | 再检查库存和条件，一次性扣料与劳作 |
| 完成饭菜 | 产出数量和目标分配 | 分配自食与招待 | 生成成品，释放原料预留并建立成品预留 |
| 上桌招待 | 人物、所选成品与可预见结果 | 确认上桌 | 扣除招待份数，进入试吃，不额外扣已包含的劳作 |
| 试吃反转 | 从强硬到愿意放行的动作和对白 | 首次观看，重复可加速 | 按公开条件计算结果，不抽隐藏失败概率 |
| 结算 | 取消哪项处理、保住什么、剩余物资 | 返回经营 | 只执行一次放行与奖励，释放任务预留 |

玩家可以在制作前更换方案。制作后原料已消耗，不能无损撤回；成品仍可保存或分配到其他符合条件的用途。上桌前再次校验，避免把错误菜品交出才得知不符合早已公开的条件。

首版不加入烹饪失败小游戏。简短表现负责操作反馈，策略挑战来自筹备与分配。关键招待不在演出中插入新的强制条件。

### 8 两个可执行流程示例

**首次野菜汤：**太监参与挖野菜 → 野菜进入库存 → 拾取秸秆 → 打开野菜汤，显示野菜与燃料齐全、固定取水点可用 → 制作两份 → 一份自食、一份招待 → 太监喝汤后改变态度 → 种子请求开放。首局保证食材和劳作充足，既不要求先获得种子，也不要求先建成完整厨房。

**后续查办：**来人要求一份不辣的热食 → 玩家比较野菜饼与清汤面 → 选择缺一份面粉的清汤面 → 面板显示太监可帮忙且能在截止前带回 → 确认请求并预留现有材料 → 到约定节点面粉入库 → 制作并分配 → 来人试吃后取消本次没收。若太监无法及时完成，则可在制作前改做现有材料够用的菜饼。

以上具体份数和配方为原型配置。野菜汤清水由固定取水点满足；后续示例的燃料按公开配方检查，不能因旧数值示例简写而遗漏真实制作条件。

### 9 例外处理与存档

- 点击制作时重新校验物资，避免同一份材料被两个行动同时使用。
- 请求尚未交付时，不允许将预计物资当作已持有。
- 剧情没收若影响已预留物资，应重新标出缺口，保留可行替代路线；预留标记不免疫剧情影响。
- 第一段查办中保留可用灶台与基础燃料渠道，避免要求做饭却无法做饭。
- 玩家退出时保存方案、预留、交付进度、成品与事件阶段；恢复演出不会再次扣料或重复发奖。
- 自然日结束点不得自动推进尚在等待玩家确认的关键招待；若关卡有游戏内截止，推进前明示后果。

### 10 表现与验证

首次试吃完整表现闻香停顿、尝一口、再吃一口、态度缓和和宣布放行；重复演出可加速，但结果文字保留。空碗、灶边热气与新摆好的桌凳让成果留在场景里，不增加额外养成指标。

验证重点是玩家能否独立完成“看要求—选菜—找料—做饭—招待”，是否因预留减少误用，是否能理解人物为什么放行。分别记录卡在查菜谱、获取物资、等待交付还是提交成品，按实际阻塞点迭代。
